# QUALITY_BAR.md — Definition of Done & Quality Standards

Defines what "done" means at every level of this research project — a task, a phase, an experimental run, and the overall research artifact. If an output fails this bar, it is not complete.

`docs/research/PROTOCOL.md` is the single source of truth. Numeric values retain status "PROPOSED" until protocol freeze. Open decisions reside in `docs/research/decision_log.md`.

---

## 1. Per-Task Quality Bar
A task is done only when ALL of the following are true:
1. The code matches the exact deliverable spec (function signatures, file paths, config keys) in the relevant implementation plan.
2. The specified test command has been executed and reported with actual green output.
3. Test failures were addressed in the implementation, not by altering the test to force a pass.
4. Only files inside the person's owned folder(s) were modified (`00_SHARED_REPO_PROTOCOL.md`).
5. Human checkpoints were verified directly by a person.

## 2. Research-Artifact Bar & Claim-to-Evidence Map

### Claim-to-Evidence Map
**Rule:** No claim in any document, paper draft, or report may exist without a direct, verifiable evidence trail.

| Claim Type | Required Evidence Source | Forbidden Patterns |
|---|---|---|
| **Clinical AUROC / AUPRC** | Matched `ExperimentRecord` in `results/registry.jsonl` with seed, config, and test split hash | Plausible estimates, numbers from other papers, untracked script output |
| **Drift Detection F1 / Delay** | Computed by `eval/detection_metrics.py` across versioned scenario configurations | Hand-tuned thresholds on test data, unversioned shift definitions |
| **DP Privacy Guarantee ($\varepsilon, \delta$)** | Realized budget from named Opacus accountant + cross-check, logged in `results/registry.jsonl` | "Nominal $\varepsilon=1.0$" without accountant verification or step counts |
| **Communication Overhead** | Measured update bytes $\times$ rounds $\times$ clients via `eval/communication_cost.py` | Theoretical parameter count estimates without transmission tracking |
| **Statistical Superiority / Invariance** | Paired tests (Wilcoxon) + 95% CIs across shared seeds ($\ge 5$; 10 preferred) | Comparing non-paired seeds, bare p-values without effect sizes |
| **Recovery Effectiveness** | Measured pre-drift, nadir, and post-recovery AUROC with fixed controller policy | Manual or oracle retraining interventions, tuned recovery windows |

## 3. PROTOCOL.md Final Checklist (Section 14)

Before declaring the research milestone complete, every box in this checklist must be verified:

- [ ] **Literature Closure**: Completed novelty check against `FedDriftGuard`, `DriftGuard`, `FedDrift`, `FedMM`, `FedMedICL`, `Med-MMFL`, and `FLamby`. Wording verified as a controlled empirical evaluation.
- [ ] **Cohort Verification**: Inclusion/exclusion rules and 24h landmark criteria verified on MIMIC-IV v3.1.
- [ ] **Subject-Level Split**: Patient-level train/validation/test separation verified with zero subject overlap.
- [ ] **Leakage Safeguards**: Automated leakage tests confirmed passing (no future observations or outcome proxies).
- [ ] **Client Partitions**: Partition sizes and mortality class balance across the 5 care units inspected and documented.
- [ ] **Privacy Definition**: Record-level DP, adjacency relation, named accountant, and cumulative ledger scope documented.
- [ ] **Achievable DP**: Pilot runs confirm candidate $\varepsilon \in \{1, 3, 8\}$ (PROPOSED) yield non-degenerate, distinguishable utility.
- [ ] **Detector Signal & Delay**: Monitored signal (client mean prediction log loss) and retrospective label delay model explicitly justified.
- [ ] **Stable False-Alarm Calibration**: Calibrated threshold on stable validation runs to ensure false-alarm rate $\le 5\%$ across stable client-windows (PROPOSED). Never tuned on test data.
- [ ] **Versioned Scenarios**: Immutable scenario configuration files with ground-truth event onsets versioned in Git.
- [ ] **Fixed Controller**: Deterministic rule-based controller (two alarms, 5-round cooldown) held strictly constant across privacy conditions.
- [ ] **Seed Count & Primary Outcome**: Seed count (at least 5; 10 preferred) and primary outcome (event-level detection F1) frozen prior to test-set evaluation.
- [ ] **Protocol Freeze**: Protocol formally frozen before running final evaluation on test splits.
- [ ] **Registry Provenance**: 100% of reported results generated by the evaluation pipeline and traceable to run configurations in `results/registry.jsonl`.

## 4. What Does NOT Count Toward "Done"
- Code that "should work" but lacks actual test execution evidence.
- A test modified to pass around a bug.
- A metric that "looks plausible" without a corresponding entry in `results/registry.jsonl`.
- Calling the system "self-evolving" without an explicit, reproducible drift-recovery trigger.
- Claiming cross-hospital generalization when partitions are derived from a single institution's dataset.
- Describing privacy guarantees as "patient-level" when using per-record DP-SGD without subject deduplication.
