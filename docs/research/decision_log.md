# Research Decision Log

Authoritative register of open experimental and protocol decisions for the study *Privacy-Aware Drift Detection in Federated Clinical Learning: Evaluating the Effect of Differential Privacy on Detection Reliability and Clinical Prediction*.

*Status Policy:* Phase 1 (federated tabular pipeline) and Phase 2 (Opacus DP-SGD infrastructure, pilot, and Part A/B/C diagnostics on synthetic cohorts) are implemented, while Phase 3 (`monitoring/` drift stream, Page-Hinkley detector, recovery controller, `viewer/`) is **not yet implemented**. Implementation notes below reflect verified Phase 2 code and validation results; no decision is marked resolved/`CLOSED` without explicit cross-team approval.

| D16 | Privacy accountant and q=1 constraint | Opacus `"rdp"` and `"prv"` accountants are implemented and cross-checked (`eval/privacy_ledger.py::track_privacy_expenditure()`), with Phase 2 runs using `"rdp"` (`epsilon_tolerance=0.01`). Under Opacus 1.5.4, `"prv"` raises `ValueError` at `sample_rate == 1.0` (`log(1 - q)` singularity), whereas `"rdp"` supports `sample_rate=1.0` and reports `rdp_only_sample_rate_1.0`. Options: (a) standardize on `"rdp"` primary + `"prv"` cross-check where `q < 1`; (b) enforce `len(train_loader) > 1` (`q < 1`) via batch-size floor so `"prv"` primary is always valid. | Standardize on `"rdp"` primary with `"prv"` cross-check when `sample_rate < 1.0` (`"divergent"` threshold guard), or enforce batch-size floor if `"prv"` sweeps are required | Ishthiyaq | Protocol freeze | OPEN |
| D17 | DP-MLP optimization, clipping/noise confounding & thresholding | Phase 2 Parts A/B/C showed `DP-Adam` + `C=1.0` produces `sens@0.5=0.0` (`mean_pos_clipping_fraction ~0.97-0.99`, positive `out.bias` drift), while Part C relaxation (`C=5, 10` at eps=8) eliminates clipping (`0.0198`, `0.0`) but couples higher `C` with proportionally larger Gaussian noise std (`sigma * C`, reducing AUROC `0.6076 -> 0.5796 -> 0.5029`, `pos@0.5` still `0`). Runtime support for `DP-SGD + momentum` (`optimizer_type="sgd"`) is implemented in `FLClient` / `server_app.py` but untested empirically. Options: (a) use Logistic Regression primary if DP-MLP remains uncalibrated; (b) benchmark `DP-SGD+momentum`, lower `C` or class-balanced/calibrated validation threshold instead of `0.5`; (c) treat Part C strictly as coupled clipping+noise sensitivity rather than pure clipping ablation. | Frame Part C explicitly as coupled clipping-and-noise sensitivity; benchmark `DP-SGD+momentum` and validation-calibrated operating thresholds before freezing Phase 3 DP-MLP | Ishthiyaq + Syed | Phase 3 / Real MIMIC-IV sweep | OPEN |
| D18 | Research scope, security & telemetry assumptions | Documented Phase 2 boundaries: (1) synthetic `generate_mock_data` cohort only (1 stay/`subject_id`; real MIMIC-IV vital/lab extraction unimplemented in `cohort.py`); (2) 5 clients are simulated care-unit partitions (`CCU, CVICU, MICU, SICU, TSICU`) of one dataset, not 5 independent hospitals; (3) `51` structured tabular features only (clinical notes, ClinicalBERT, chest X-rays, and multimodal fusion are NOT implemented); (4) single-process execution via `LocalClientProxy` with **no Secure Aggregation (`SecAgg`)** — server receives plaintext weights; (5) `secure_mode=False` (non-cryptographic seeded research RNG); (6) validation evaluation and Part B/C gradient telemetry (`p.grad_sample`, heuristic `>=20` suppression) are non-DP (`is_dp_guarantee=False`, `diagnostic_telemetry_covered_by_dp=False`). | Ratify as formal study scope and paper limitations (`model_parameters_only`, no end-to-end DP claimed); verify real MIMIC-IV single-site runs separately before clinical claims | All | Protocol freeze / Paper draft | OPEN |
